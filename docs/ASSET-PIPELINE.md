# 素材管线：把实拍 / 网图变成能用的平涂素材

2026-09-20 由「高达 00Q 指针套装」项目沉淀。那份项目从 **11 张手机实拍** 做出了
15 个成品指针（含 11 个动画），这条管线就是它的主干。

**适用**：手上有一张实物照 / 截图 / 网络图，需要变成干净的平涂素材
（图标、道具、UI 元件、光标……），并且最终会**缩到很小**使用。

**不适用**：需要从零创作 → 走 `SKILL.md` 的 t2i 配方。

---

## 一、七步管线

```
① 验文件头 → ② 裁切 → ③ BiRefNet 抠图 → ④ 摆正 → ⑤ Qwen 洗成平涂
→ ⑥ 反推 alpha + 描边 → ⑦ 色调校正
```

每一步都有实测出来的坑，逐条如下。

### ① 验文件头（**这条被踩了 5 次**）

```python
Image.open(p).format     # 别信扩展名
```

用户给的"PNG"里，**5 张是 JPEG**（`\xff\xd8\xff`）。后果不是报错，
而是某些工具**静默按错误格式解码**，颜色/alpha 全乱。

> **规矩：每拿到一张新素材，第一件事是 `Image.open(p).format` 打出来。**

### ② 裁切

按主体留 10~15% 余量。**不要裁得太紧** —— 下一步 BiRefNet 需要一点上下文。
裁切前先打 10% 网格（`scripts` 见项目 `tools/grid_view.py` 思路）确认范围。

### ③ BiRefNet 抠图

```bash
python "$SK/scripts/comfygen.py" matte <图> --alpha --out <目录>
```

实测前景占比 10~30% 是正常的；**50% 通常意味着背景被当成主体了**，要回头查裁切。

### ④ 摆正（PCA，不要肉眼估）

```python
ys, xs = np.nonzero(alpha > 16)
P = np.stack([xs, ys], 1); c = P.mean(0)
_u, _s, vt = np.linalg.svd(P - c, full_matrices=False)
ang = degrees(arctan2(vt[0][1], vt[0][0]))    # 主轴角
im.rotate(ang - 90)                            # 转到竖直
```

⚠️ **`rotate(θ)` 把方向 φ 映射到 `φ − θ`**。要转到目标角 `T`，传 `a0 − T`。
**这个符号错了整张图会转到完全无关的方向**（实测踩过：把图转成了竖直，
模板匹配的 F1 恒为 0，查了半天才发现是旋转方向反了）。

### ⑤ Qwen 洗成平涂

用 `Qwen-Image-Edit-2509`，prompt 保持**极简**：

```
Clean up this illustration: flat cel-shaded anime style, solid flat color
blocks, bold clean outlines, keep the exact same colors as the original,
remove all surface texture and noise. Keep every part in exactly the same
place with exactly the same shape and proportions.
```

> ★ **一描述具体部件，Qwen 就会把那部分重画。** 想要什么改动就直说，
> 不想改就只写"风格 + 保持原样"。实测：加了 `vivid saturated colors`
> 会把灰件洗成米黄；写 `keep the exact same colors` 也压不住（见 ⑦）。

**比例**：`prep` 会把图补到 ≤3:1。原件是 **5.5:1 的长条时先转到 45°** 再洗 ——
转完包围盒接近正方形，那才是 Qwen 最舒服的输入比例。

### ⑥ 反推 alpha + 描边

按"与背景色的距离"判前景，再给外围加一圈描边。**但见下面的 ② 号规律 ——
这条判据在"主体颜色接近背景"时会整体失效。**

### ⑦ 色调校正

Qwen 有**系统性偏色**，实测 3 次全是同一模式：

| | 洗前 | 洗后 | |
|---|---|---|---|
| 白甲 | (189,190,185) 暖白 | (149,160,170) **冷蓝灰** | 白了变蓝、变暗 |
| 手指 | (187,185,181) | (91,90,103) **近黑** | 中间调压死 |
| 发射器 | 偏暖 +16 | 偏暖 **+42** | 饱和推过头 |

**做法**：`tools/asset_tone.py` —— **按亮度渐入的增益** + 整体去饱和。

```python
t = clip((V - lo) / (hi - lo), 0, 1)      # 渐入权重
rgb *= 1 + (gain - 1) * t                 # 暗部不动，亮部才拉
rgb = gray + (rgb - gray) * sat           # 去色偏
```

⛔ **不能直接 `V *= k`** —— 会把**描边（V≈30~40）一起提亮**，线条发灰。

★ **`lo/hi` 是选择性开关**：压到 `140/150` 就等于"只提白件，不动手指和描边"。
实测白甲 `(141,158,164) → (213,218,220)`，其余不变。

## 二、八条跨项目成立的规律

### ① 像素单位必须**逐档给**（这个项目踩了 6 次）

缩放在**最后**做，所以任何以像素计的尺寸（描边宽、模糊半径、腐蚀量、
粒子半径、刻线宽、位移量）都必须在**该档自己的分辨率**上算。

> 反复出现的同一个 bug：在 512 母版上出帧再缩到 32px ——
> 3px 的粒子缩完只剩 0.19px，**直接消失**；光晕被平均成灰雾。
>
> 还有超采样版：在 4× 画布上画 2px 的线，缩回 1× 只剩 **0.5px**，刻线糊没。
> ⇒ 细线宽要写成 `max(SS, int(S * 0.020))`（`S*0.020` 对应最终 1px，`SS` 兜底）。

### ② 判据要用**结构**，不要用**颜色距离**

抠图的 alpha 判定是重灾区：

- `finish` 用"与背景色的距离"→ 主体里有**深灰件（V≈85）**而背景 V≈68 时，
  **距离只有 16，整块主体被当背景抹掉**（实测输出只剩白色部分）。
- ⇒ 改用**从画面边界泛洪**：背景是连通到边界的均匀色块，
  而每个零件都被**深色描边**圈住 ⇒ 泛不到的就是前景。

⚠️ 泛洪必须带 **`FLOODFILL_FIXED_RANGE`**（每个像素与**种子**比较）。
默认模式跟**邻域**比较，能顺着抗锯齿的渐变**一路爬过描边** ——
实测 `tol=22` 时前景只剩 672px（整张被淹）。

### ③ 否定式断言在裁剪/越界 bug 下**恒为真**

"零重叠 / 零报错 / 都在画布内"这类检查，在形状被裁到画布外时**依然通过**。
⇒ 先验一个**肯定的事实**（单独渲染一个件、量它的实际 bbox），
再谈否定式的结论。

### ④ 改比例前先**量参考**

"手太粗糙了，改纤细一点" —— 我拍脑袋把手指拉长到拳头的 1.37 倍，
**整体看着像瓶子**。回头量参考才发现原作的"指长/拳高 = 0.92"。

> **量占比，别量坐标。** 复刻类任务（"把这个形状复刻出来"）尤其如此 ——
> 占比对了一眼就像，坐标对了但比例错还是不像。

### ⑤ 复刻线条时先判断：**开口折线**还是**闭合轮廓**

实拍上一条**贯穿**零件的折线，我读成"凸字形"，画成了**闭合图形** ——
凭空多出三条边，整块面板变成"里面套一个凸"。

> 用户说的是"那是一条**凸的**线"（描述**走向**），不是"画个凸字"。
> **这是"把手段当成了目的"，和 ⑥ 是同一类错误。**

### ⑥ "怎么切"很别扭时，先回头问**"该不该切"**

要"把合体件沿接缝分成两半"，我在**合体件自己的轮廓上**找了两版切线
（腰部 → 中点 → 模板匹配）。正确做法是**根本不切** —— 素材库里本来就有
**单件的图**，直接摆两个单件、让它们重叠 = 合体态。

> 附带教训：**"对接处必然收窄"这种几何直觉也可能是错的**。
> 实测那个件的对接处横截面**反而最宽**，"腰部"启发式挑到了完全错误的位置。
> **能量化的先量化。**

### ⑦ 旋转动画有**车轮效应上限**

多重对称的形状，**每帧转角 ≥ 对称角的一半**就会被看成静止或倒转。

| 对称重数 | 对称角 | 每帧上限 |
|---|---|---|
| 4 重（十字旋翼） | 90° | **< 45°** |
| 6 重 | 60° | < 30° |

实测：十字转 4 圈/32 帧 = 45°/帧，**取样的 6 帧完全一样，等于没转**。
⇒ 上限是 2 圈/32 帧 = 22.5°/帧。

### ⑧ 动画要让**光跟着形走**

发光/粒子/描边如果用了**静态掩码**，形状动起来就是"形在转、光不转"，
或者张开时**缝隙里也有光**（看着像一层雾而不是真的分开了）。
⇒ 每帧从**当前合成结果**重新取掩码。

## 三、细长物体的尺寸几何（**别信"45° 能多塞 41%"**）

小尺寸下细长物会退化成一根线（`SKILL.md` §3 已知坑）。斜置能救一点，但**没有想象的多**：

```
L×W 的矩形转 45° 后，包围盒 = (L+W)/√2 ≤ S
⇒ L ≤ S·√2 / (1 + W/L)
```

| 长宽比 | 45° 相对竖直多出的长度 |
|---|---|
| 无限长（W→0） | +41% |
| **3.6 : 1** | **只有 +12%** |
| 5.6 : 1 | +18% |

> 我第一次按"零宽度长条"估成 41%，实际这个件只有 12% —— **不值得为它改姿态**。
> 真正的解法是 ④：**回参考量比例**，或者接受"手/机身之类有体量的部件
> 反而帮了忙"（光剑单独 5.6:1 → 加了手变 3.6:1，小尺寸下更好认）。

## 四、交付前必做

```bash
python "$SK/scripts/comfygen.py" check <素材> --sizes 16,32,64,128
```

外加本项目加的两条：

1. **从成品容器里读回来复验**（不是看源文件）—— 打包格式、alpha、hotspot
   都可能在这一步出问题，只看 PNG 是发现不了的。
2. **把"感知强度"也量出来**。动画幅度"太小了感知不强"这种反馈，
   量化后才有抓手：逐帧量**特征点的位移**，用数字说明改前改后。
